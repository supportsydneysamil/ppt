# 커스텀 슬라이드 템플릿 · 테마 설계

## 목표

커스텀 슬라이드 편집기에 교회 예배에서 자주 쓰는 레이아웃을 더하고, 템플릿과 따로 고를 수 있는 색 테마를 둔다. 테마를 바꿔도 문구·이미지·구도는 유지하고 색만 바뀐다.

## 범위

포함:

- 커스텀 편집기 템플릿을 **15개**로 구성 (빈 슬라이드 + 기존 4 디자인 + 새 10개)
- 색 테마 **21개** (네이티브 1 + 전역 팔레트 20)
- 템플릿 옆 **테마** 선택 UI
- 역할(`themeRole`) 기준으로 배경·글자·도형 색만 교체
- PPTX/미리보기는 이미 모델의 `fill`/`color`/`stroke`/`background.color`를 쓰므로 색을 모델에 구운 뒤 기존 경로를 그대로 사용

제외:

- 주일예배 타이틀 카탈로그·시즌 테마와의 연동
- 사용자 정의 팔레트 저장
- 이미지 픽셀 재채색, 그라데이션, 사진 필터
- 테마마다 레이아웃을 다르게 하는 일
- 메인 예배 템플릿 갤러리(`data/templates.json`) 변경

## 편집기 동작

상단 바에 지금 있는 **템플릿** 선택과 **템플릿 적용** 버튼은 유지한다. 그 옆에 **테마** `<select data-custom-editor="theme">`를 둔다.

- **템플릿 적용**은 지금처럼 캔버스를 해당 템플릿 모델로 교체한다. 적용 시점의 테마로 색을 입힌다. 빈 슬라이드면 요소가 없고 테마 배경색만 쓴다.
- **테마 변경**은 확인 버튼 없이 즉시 적용한다. 요소 위치·크기·회전·텍스트·이미지 src는 건드리지 않는다.
- 배경색 피커로 고른 색은 그 상태로 둔다. 테마를 고르면 그 테마의 배경색이 피커 값을 덮는다.
- 저장·내보내기 모델에는 구워진 색과 함께 `themeId`를 넣는다. 옛 슬라이드에 `themeId`가 없으면 드롭다운은 `native`로 보여주고 자동으로 다시 칠하지 않는다.
- 알 수 없는 `themeId`는 `native`로 본다.

## 색 역할

전역 팔레트와 템플릿 네이티브 팔레트는 같은 키를 쓴다.

| 역할 | 쓰는 곳 |
|---|---|
| `background` | 슬라이드 배경 |
| `surface` | 카드, 사진 자리, 패널 |
| `accent` | 가로·세로 강조 막대, 구분선 |
| `title` | 큰 제목 |
| `body` | 본문, 가사, 목록 |
| `muted` | 시리즈명, 장절, 출처, “이미지를 추가하세요” |
| `stroke` | 카드 테두리처럼 선이 있는 도형 |

규칙:

- 텍스트는 `color`를 역할 색으로 바꾼다.
- 도형은 `fill`을 역할 색으로 바꾼다. `strokeWidth`가 0이거나 `stroke`가 비어 있으면 선을 만들지 않는다.
- 선(`type: "line"`)은 `stroke`를 `accent`로 바꾼다.
- `themeRole`이 없는 요소(사용자가 새로 그린 것, 이미지)는 테마를 바꿔도 그대로 둔다.
- 속성 패널에서 채우기·글자색·선색을 직접 바꾸면 그 요소의 `themeRole`을 지운다. 이후 테마 변경이 손본 색을 덮지 않는다.
- 배경 피커는 슬라이드 배경만 바꾸고 `themeId`는 그대로 둔다. 다음에 테마를 고르면 배경이 다시 테마 값을 따른다.

네이티브는 전역 팔레트가 아니다. 각 템플릿 정의가 자기 `nativePalette`를 가진다. 테마가 `native`이면 그 슬라이드를 만들 때 쓴 템플릿 id의 네이티브 팔레트로 역할이 남은 요소만 되돌린다. 빈 슬라이드의 네이티브 배경은 `#ffffff`이다.

템플릿 정의의 요소는 처음부터 `themeRole`을 달고, 동시에 네이티브 색을 `fill`/`color`/`stroke`에 넣는다. `CUSTOM_SLIDE_TEMPLATES`에 올리는 기본 모델은 네이티브 색이다.

## 템플릿 목록

캔버스는 기존과 같이 1280×720이다. 새 정의는 `TEMPLATE_DEFINITIONS`에 두고, `CUSTOM_SLIDE_TEMPLATES`로 정규화한다. `instantiateTemplate(id)`는 지금처럼 새 요소 id를 부여하고, 선택된 `themeId`로 색을 입힌 모델을 반환한다. 시그니처는 `instantiateTemplate(templateId, idFactory, themeId)`로 늘린다. `themeId`를 생략하면 `native`다. 없는 템플릿 id는 지금처럼 빈 슬라이드다.

| id | 라벨 | 구도 | 역할 배치 |
|---|---|---|---|
| `blank` | 빈 슬라이드 | 요소 없음 | 배경만 |
| `title-hero` | 타이틀 히어로 | 가운데 가로 밴드, 제목·부제 | 밴드 `accent`, 제목 `title`, 부제 `muted`, 배경 네이티브 `#0f172a` |
| `split-photo` | 좌우 분할 (사진) | 왼쪽 패널 + 오른쪽 제목·본문 | 패널 `surface`, 힌트 `muted`, 제목 `title`, 본문 `body` |
| `quote-card` | 인용 카드 | 가운데 카드, 짧은 막대, 인용, 출처 | 카드 `surface`+`stroke`, 막대 `accent`, 인용 `body`, 출처 `muted` |
| `agenda-list` | 예배 순서 | 제목, 가로줄, 번호 목록 | 제목 `title`, 줄 `accent`, 목록 `body` |
| `scripture` | 성경 본문 | 왼쪽 세로 강조, 큰 구절, 작은 장절 | 세로막대 `accent`, 구절 `title`, 장절 `muted` |
| `lyrics` | 찬양 가사 | 상단 곡명, 가운데 가사 2~4줄 | 곡명 `muted`, 가사 `title` |
| `sermon-title` | 설교 제목 | 시리즈명, 짧은 막대, 제목, 본문·설교자 | 시리즈 `muted`, 막대 `accent`, 제목 `title`, 메타 `body` |
| `sermon-points` | 설교 요점 | 짧은 제목 + 본문 2~4개 요점 | 제목 `title`, 요점 `body` |

| `creed` | 공동 고백·기도문 | 작은 제목 + 큰 고정 문구 | 제목 `muted`, 본문 `body` |
| `prayer` | 기도 제목 | 제목 + 번호 목록 | 제목 `title`, 목록 `body` |
| `welcome` | 환영 | 큰 한 줄 + 안내 부제 | 환영 `title`, 안내 `muted` |
| `offering` | 봉헌 | 짧은 안내 + 선택 구절 한 줄 | 안내 `title`, 구절 `muted` |
| `next-week` | 다음 주 안내 | 왼쪽 큰 날짜(요일·일), 오른쪽 예배명·시간·장소 | 날짜 `title`, 상세 `body`, 작은 라벨 `muted` |

기존 네 디자인(`title-hero`, `split-photo`, `quote-card`, `agenda-list`)의 좌표와 문구는 유지하고 `themeRole`만 붙인다. 새 열 개는 기존 도형·텍스트 타입만 사용한다. 이미지 파일은 넣지 않는다. `split-photo`는 지금처럼 회색 패널과 힌트 텍스트다.

플레이스홀더 문구는 한국어로, 예배에서 바로 고쳐 쓸 수 있게 둔다. 예: 성경 본문은 구절 자리와 `요한복음 3:16`, 가사는 `가사를 입력하세요`, 설교 제목은 시리즈·제목·`본문 · 설교자`, 공동 고백은 `사도신경`과 첫 문장 몇 줄, 봉헌은 `하나님을 찬송하는 마음으로 드립니다`.

## 모델

`normalizeCustomSlide`가 다음을 보존한다.

- 슬라이드: `themeId` (문자열, 목록에 없으면 `native`)
- 요소: `themeRole` (위 역할 중 하나. 없거나 잘못되면 필드를 빼서 “역할 없음”으로 둔다)

`cloneCustomSlide` / `instantiateTemplate`은 `themeRole`을 복사한 뒤 테마 색을 입힌다. Fabric 직렬화 왕복에도 `themeRole`이 남는다. PPTX 쪽은 색 필드만 보면 되므로 `themeRole`을 몰라도 된다.

## 구조

색 목록과 `applyTheme(model, palette)`는 템플릿 배열과 분리된 모듈(또는 `custom-slide-editor.js` 안의 순수 함수 구간)에 둔다. 컨트롤러는 테마 select 변경 때 현재 모델을 읽어 적용하고 캔버스를 다시 그린다. `index.html`에 테마/템플릿 옵션을 하드코딩하지 않는다. 지금 템플릿 옵션을 모듈에서 채우는 방식과 같다.

## 테스트

- 템플릿 id·라벨이 15개이고 중복이 없다. 빈 슬라이드만 요소가 없다.
- 디자인 템플릿은 모두 `themeRole`을 가진 요소가 있다.
- `instantiateTemplate`은 요소 id를 새로 만들고, `themeId`를 주면 해당 팔레트 색이 배경·역할 요소에 들어간다. `native`면 정의의 원래 색이다.
- `applyTheme`은 텍스트와 좌표를 바꾸지 않고, `themeRole` 없는 요소와 이미지는 건드리지 않는다.
- 잘못된 색을 고치면 그 요소의 `themeRole`이 사라진다.
- 컨트롤러: 테마 select가 모듈 목록에서 채워지고, 테마 변경이 캔버스 배경색을 바꾼다.
- 기존 단축키·스냅·정규화 테스트는 그대로 통과한다.

## 성공 기준

편집기에서 15개 레이아웃을 고를 수 있고, 21개 테마 중 아무것이나 고르면 같은 글이 다른 색으로 보인다. 네이티브가 마음에 없으면 다른 테마로 바로 바꿀 수 있다.
