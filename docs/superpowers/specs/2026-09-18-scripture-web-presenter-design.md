# 성경 웹 뷰 발표 모드 설계

## 목표

성경텍스트의 웹 뷰를 예비 즉석 프레젠테이션 도구로 개선한다. 사용자가 웹 뷰를 누르면 별도 팝업이 열리고 전체화면 진입을 즉시 시도한다. 브라우저 정책으로 자동 전체화면이 거절되어도 한 번의 명확한 클릭으로 발표를 시작할 수 있어야 한다.

웹 뷰는 PowerPoint를 대체하는 편집기가 아니라, 준비된 성경 본문을 현장에서 빠르고 안정적으로 보여 주는 백업 발표 화면이다.

## 범위

포함:

- 기존 팝업 방식 유지
- 팝업 차단 감지와 해제 안내
- 로드 직후 전체화면 진입 시도
- 자동 전체화면 실패 시 큰 「전체화면으로 시작」 버튼
- 전체화면 발표 중 상단 UI 자동 숨김
- 화면 정중앙의 16:9 슬라이드와 검정 여백
- 키보드, 마우스, 터치 기반 슬라이드 이동
- 검정 화면 전환
- 발표 중 현재 장수 확인과 컨트롤 재표시

제외:

- 발표자 노트와 발표자 전용 창
- 듀얼 모니터 제어
- 슬라이드 썸네일 목록
- 성경 본문 편집
- PPT 생성기 슬라이드나 템플릿과의 동기화
- 오프라인 저장 및 서버 재시작 후 세션 복원
- 웹 뷰용 말씀/봉독 제목 슬라이드 추가

제목 슬라이드는 이번 1차 범위에서 제외한다. 먼저 현장 조작과 전체화면 안정성을 확보한 뒤 필요하면 별도 개선으로 추가한다.

## 열기 흐름

1. 사용자가 성경텍스트 결과 화면에서 「웹 뷰」를 누른다.
2. 클릭 이벤트 안에서 즉시 `window.open()`을 호출해 현재처럼 별도 팝업을 만든다.
3. 팝업은 로딩 화면을 먼저 표시하고, 메인 창은 웹 뷰 세션을 생성한다.
4. 세션 생성이 완료되면 팝업을 웹 뷰 URL로 이동한다.
5. 웹 뷰가 데이터를 그린 직후 `requestFullscreen()`을 최선 시도로 호출한다.
6. 성공하면 바로 발표 모드로 들어간다.
7. 브라우저의 사용자 활성화 정책으로 거절되면 슬라이드 위에 큰 「전체화면으로 시작」 버튼과 `F` 안내를 표시한다. 사용자가 버튼을 누르면 같은 팝업에서 전체화면으로 들어간다.

새 팝업의 사용자 활성화는 브라우저마다 다르므로 자동 전체화면 성공을 보장하지 않는다. 실패는 오류 화면이 아니라 정상적인 대체 흐름으로 처리한다.

## 팝업 차단 처리

`window.open()`이 `null`을 반환하거나 즉시 닫힌 상태이면 메인 화면에 경고를 표시한다.

- 메시지: 「팝업이 차단되었습니다. 주소창의 팝업 허용을 켠 뒤 다시 시도하세요.」
- 동작: 사용자가 허용 후 같은 「웹 뷰」 버튼을 다시 누를 수 있다.
- 새 탭 자동 대체는 하지 않는다.
- 세션 생성은 팝업이 정상적으로 열린 뒤에만 진행하여 사용되지 않는 세션을 만들지 않는다.

세션 생성이나 데이터 로딩이 실패하면 팝업 안에 오류 메시지와 「창 닫기」 동작을 제공한다. 메인 창도 기존 경고를 유지한다.

## 발표 화면

기본 창 모드에서는 현재 구절 제목, 장수, 이전·다음, 전체화면 버튼을 상단 컨트롤에 표시한다.

전체화면에서는 다음 규칙을 적용한다.

- 배경 전체를 검정으로 채운다.
- 16:9 슬라이드를 가용 영역 안에서 비율을 유지하며 최대 크기로 확장한다.
- 슬라이드는 가로·세로 모두 정확히 중앙에 둔다.
- 상단 컨트롤과 마우스 커서는 기본적으로 숨긴다.
- 마우스를 움직이거나 화면 상단을 누르면 컨트롤을 표시하고 2.5초 뒤 다시 숨긴다.
- 키보드 포커스가 컨트롤 안에 있거나 포인터가 컨트롤 위에 있으면 숨김 타이머를 멈춘다.
- 전체화면을 종료하면 상단 컨트롤을 다시 항상 표시한다.

전체화면 진입 여부는 `fullscreenchange`를 기준으로 갱신한다. 버튼 호출 성공 여부만 믿지 않는다.

## 조작

슬라이드 이동:

- 다음: `ArrowRight`, `ArrowDown`, `PageDown`, `Space`, 화면 오른쪽 영역 클릭
- 이전: `ArrowLeft`, `ArrowUp`, `PageUp`, 화면 왼쪽 영역 클릭
- 첫 장: `Home`
- 마지막 장: `End`
- 터치: 왼쪽 스와이프는 다음, 오른쪽 스와이프는 이전

발표 제어:

- 전체화면 진입/재진입: `F` 또는 전체화면 버튼
- 전체화면 종료: 브라우저 기본 `Esc`
- 검정 화면 전환: `B`

검정 화면에서는 슬라이드와 컨트롤을 가리고 완전한 검정을 표시한다. `B`를 다시 누르면 같은 슬라이드로 복귀한다. `Esc`는 브라우저 전체화면 종료에 맡기며 검정 화면 단축키로 사용하지 않는다.

폼 컨트롤이나 버튼에 포커스가 있을 때는 `Space`를 슬라이드 이동으로 가로채지 않는다. 첫 장에서 이전, 마지막 장에서 다음 입력은 아무 동작도 하지 않는다.

## 접근성과 상태 표시

- 전체화면 버튼은 현재 상태에 따라 「전체화면」 또는 「전체화면 종료」로 바뀐다.
- 검정 화면 버튼은 `aria-pressed`로 상태를 알린다.
- 슬라이드 장수는 화면과 보조기술 모두에 갱신한다.
- 전체화면 실패 안내는 포커스를 받을 수 있고, 버튼 클릭 후 사라진다.
- 터치 영역은 화면을 보이지 않게 덮는 별도 버튼으로 만들지 않고 스테이지 포인터 좌표로 판정하여 본문을 가리지 않는다.
- `prefers-reduced-motion`에서는 컨트롤과 안내 오버레이 전환 애니메이션을 제거한다.

## 데이터와 서버

기존 `POST /api/scripture/web-view-session`과 `GET /api/scripture/web-view-session/:sessionId`를 유지한다. 본문 분할, 테마, 사용자 배경 이미지 데이터 형식도 바꾸지 않는다.

세션은 현재처럼 서버 메모리에 30분 동안 유지한다. 웹 뷰가 데이터를 한 번 받은 뒤에는 브라우저 메모리의 데이터를 사용하므로 발표 도중 세션 만료가 현재 슬라이드 이동을 중단시키지 않는다. 서버 재시작과 페이지 새로고침 후 세션 소실은 이번 범위에서 해결하지 않는다.

전체화면과 검정 화면 상태는 저장하지 않는다. 페이지를 새로 열거나 새로고침하면 첫 슬라이드, 비전체화면, 비검정 상태로 시작한다.

## 구현 경계

- `public/app.js`: 팝업 생성, 차단 감지, 세션 생성, 팝업 이동 및 메인 화면 오류 처리
- `public/scripture-web-view.html`: 전체화면 시작 안내, 전체화면·검정 화면 컨트롤 추가
- `public/scripture-web-view.js`: Fullscreen API, 발표 상태, 이동 단축키, 클릭·스와이프, 컨트롤 자동 숨김
- `public/scripture-web-view.css`: 전체화면 레이아웃, 중앙 정렬, 검정 화면, 안내 오버레이, 컨트롤 표시 전환
- `server.js`: 기존 세션 API와 페이로드를 그대로 사용하며 변경하지 않는다.

발표 상태는 웹 뷰 스크립트 안에서 `isFullscreen`, `isBlackout`, `controlsVisible`로 분리한다. 슬라이드 인덱스 변경과 화면 모드 변경이 서로의 상태를 암묵적으로 바꾸지 않게 한다.

## 실패 처리

- Fullscreen API가 없으면 자동 시도를 생략하고 「이 브라우저에서는 전체화면을 지원하지 않습니다」를 표시한다. 창 모드 발표는 계속 가능하다.
- `requestFullscreen()`이 거절되면 콘솔 오류만 남기지 않고 시작 안내를 표시한다.
- 전체화면이 외부 원인으로 종료되면 상태와 버튼 문구를 즉시 복구한다.
- 팝업 크기가 지나치게 작아도 슬라이드는 비율을 유지하며 축소한다.
- 스와이프는 최소 이동 거리와 수평 우세 조건을 모두 충족할 때만 처리하여 세로 스크롤이나 가벼운 터치를 오인하지 않는다.
- 배경 이미지가 로드되지 않으면 기존 테마 배경색으로 본문을 계속 표시한다.

## 검증

자동 검증:

- 전체화면 성공·거절·미지원 상태별 안내와 버튼 상태
- `fullscreenchange` 발생 시 발표 모드 진입·종료
- 모든 이동 키와 첫 장·마지막 장 경계
- 버튼에 포커스된 `Space`를 가로채지 않는지
- 좌우 클릭 영역과 스와이프 방향
- `B` 검정 화면 전환 후 같은 슬라이드 유지
- 전체화면에서 컨트롤 표시 후 타이머로 숨김
- 팝업 차단 시 세션 요청을 보내지 않고 안내하는지
- 기존 웹 뷰 페이로드와 본문 렌더링 유지

수동 검증:

- Chrome과 Safari에서 팝업 허용 상태로 웹 뷰 열기
- 자동 전체화면 성공 시 바로 슬라이드만 표시되는지
- 자동 전체화면 거절 시 큰 버튼 한 번으로 진입하는지
- 팝업 차단 후 안내에 따라 허용하고 재시도할 수 있는지
- 프로젝터 비율과 일반 노트북 창에서 슬라이드가 중앙에 유지되는지
- 키보드, 마우스, 터치로 끝까지 이동하고 검정 화면에서 복귀하는지
