# PPT 생성기 저장 상태 및 팝업 설계

## 목표

PPT 생성기의 일반 슬라이드와 템플릿 작업 공간에서 실제로 저장할 변경이 있을 때만 저장 버튼을 활성화한다. 저장 성공 후에는 버튼을 비활성화하고, 미저장 변경을 가진 채 이동할 때는 중복 없는 하나의 팝업으로 저장·폐기·취소를 선택하게 한다.

## 범위

- 슬라이드 편집기의 `저장` 버튼
- 템플릿 작업 공간의 구조 커맨드(순서, 추가, 삭제, 복제, 이름)
- 슬라이드 선택, PPT 탭 전환, 템플릿 열기와 닫기, 메인 화면 전환
- 저장 성공·실패 알림
- 브라우저 새로고침과 닫기 경고
- 일반, 광고, 찬송가, 성경 말씀, 타이틀, Custom 타이틀, 업로드 슬라이드

슬라이드 순서 변경과 템플릿 이름 변경처럼 편집기 밖에서 일어나는 템플릿 변경은 초안이 아니라 커맨드이므로, 메인 슬라이드 목록과 같은 규칙으로 즉시 반영하고 실패하면 되돌린다. 따라서 대기 상태로 남지 않는다.

2026-09-14 개정: 템플릿 편집의 2단계 저장을 없애고 경계를 API로 옮겼다. 아래 본문은 그 개정을 반영한다.

## 확인된 문제

1. `hasUnsavedChanges`가 바뀌어도 슬라이드 저장 버튼 상태를 갱신하지 않아 버튼이 항상 활성화되어 있다.
2. boolean만으로 변경을 추적하므로 값을 저장 상태로 되돌려도 dirty 상태가 해제되지 않는다.
3. 템플릿 변경과 현재 슬라이드 변경이 동시에 있으면 이동 확인이 두 번 표시될 수 있다.
4. 메인 화면 전환은 템플릿 dirty 상태를 확인하지 않아 변경 경고를 건너뛸 수 있다.
5. 저장 API 성공 전에 슬라이드 객체를 `saved=true`로 바꾸므로 API 실패 후 화면과 서버 상태가 달라질 수 있다.
6. 찬송가 로드, 성경 슬라이드 생성, PPT 변환 등 일부 작업이 저장본 객체를 미리 수정해 리셋이나 폐기가 정확하지 않을 수 있다.
7. 템플릿에는 전체 교체(`PUT /api/templates/:id`) 하나뿐이라 이름·순서·모든 슬라이드 내용이 한 요청에 섞였다. 그 위에서는 어떤 UI를 올려도 슬라이드 저장이 순서를 덮어쓰는 것을 막을 수 없고, 슬라이드를 저장한 뒤 템플릿 저장을 또 눌러야 했다.
8. 브라우저 새로고침이나 닫기 시 미저장 변경 경고가 없다.

## 상태 모델

### 슬라이드 편집 상태

슬라이드를 선택하거나 저장에 성공할 때 직렬화된 기준 스냅샷을 만든다. 현재 폼 값과 아직 저장되지 않은 파일 선택을 같은 정규화 규칙으로 직렬화해 기준 스냅샷과 비교한다.

- `slideDirty`: 현재 편집 초안과 기준 스냅샷이 다름
- `slideSaving`: 슬라이드 저장 작업 진행 중
- 새 슬라이드: 기준 저장본이 없으므로 처음부터 `slideDirty=true`

값을 수정한 뒤 기준값과 완전히 같게 되돌리면 `slideDirty=false`가 된다. 파일 입력은 파일 이름, 크기, 최종 수정 시각 등 안정적인 메타데이터로 변경 여부를 표현하고 실제 파일 객체는 직렬화하지 않는다.

### 템플릿 상태

템플릿 레벨 변경에는 대기 상태가 없다. 순서, 추가, 삭제, 복제, 이름 변경은 각자의 엔드포인트로 즉시 기록되고, 실패하면 화면과 메모리를 직전 상태로 되돌린다.

- `structureSaving`: 구조 커맨드 요청 진행 중
- 템플릿 캐시는 서버 응답으로만 교체한다. 아직 저장되지 않은 로컬 슬라이드는 절대 캐시에 쓰지 않는다.

### 저장 버튼

- 슬라이드 `저장`: 현재 슬라이드가 있고 `slideDirty=true`이며 저장 중이 아닐 때만 활성. 템플릿 작업 공간에서도 같다. 순서를 바꿔도 이 버튼은 켜지지 않는다.
- 템플릿 작업 공간에는 별도의 저장 버튼이 없다. 구조 커맨드가 이미 기록을 마쳤기 때문에 저장을 기다리는 것이 남지 않는다.
- 저장 요청 중에는 중복 요청을 막기 위해 버튼을 비활성화하고 진행 문구(`저장 중...`)를 표시
- 실패 시 기준 스냅샷을 갱신하지 않아 저장 버튼이 다시 활성화됨

### 범위를 강제하는 API

경계는 규약이 아니라 엔드포인트의 형태로 막는다. 슬라이드 저장 요청에는 순서 파라미터도 이름 파라미터도 없다.

- 슬라이드 레벨: `POST /api/templates/:id/slides`(최초 저장), `PUT /api/templates/:id/slides/:slideId`(내용 교체)
- 템플릿 레벨: `PUT /api/templates/:id/slide-order`, `DELETE /api/templates/:id/slides/:slideId`, `POST /api/templates/:id/slides/bulk-delete`, `POST /api/templates/:id/slides/:slideId/duplicate`, `PATCH /api/templates/:id`

각 라우트는 `lib/template-store.js`의 순수 함수에 위임하고, 그 변경으로 더 이상 참조되지 않는 업로드만 정리한다. 같은 템플릿의 다른 슬라이드가 아직 쓰는 경로는 지우지 않는다.

## 데이터 흐름

1. 슬라이드 선택 시 저장된 모델을 복제해 편집 초안을 만들고 기준 스냅샷을 기록한다.
2. 모든 입력, 토글, 파일 선택, 자동 이름 변경은 중앙 변경 감지 함수를 호출한다.
3. 저장 클릭 시 초안을 검증하고 업로드나 PPT 생성을 수행한다.
4. 일반 슬라이드는 서버 저장이 성공한 뒤에만 저장 모델과 기준 스냅샷을 교체한다.
5. 템플릿 내부 슬라이드는 그 슬라이드 하나만 서버에 보내고, 성공 응답의 템플릿으로 캐시와 작업 목록을 교체한다.
6. 구조 커맨드도 같은 방식으로 응답의 템플릿을 그대로 받아 적용한다.
7. 실패한 업로드나 생성 결과는 저장 기준에 반영하지 않는다.

## 이동 팝업

모든 앱 내부 이동은 하나의 이동 가드를 거친다.

- 대상: 다른 슬라이드 선택, PPT 탭 전환, 템플릿 열기와 닫기, 메인 화면 전환
- 조건: `slideDirty`(새 미저장 슬라이드 포함). 구조 변경은 이미 서버에 있으므로 조건이 아니다.
- 변경이 없으면 팝업 없이 즉시 이동

팝업은 다음 세 동작을 제공한다.

1. `저장 후 이동`
   - 현재 슬라이드를 서버에 저장한 뒤 이동한다. 메인 목록과 템플릿 모두 같다.
   - 저장 실패 시 팝업을 닫지 않고 이동도 수행하지 않음
2. `저장하지 않고 이동`
   - 새 슬라이드는 작업본에서 제거
   - 기존 슬라이드 초안은 기준 스냅샷으로 복원
   - 복원 후 이동
3. `계속 편집`
   - 팝업만 닫고 현재 상태 유지

팝업이 물을 수 있는 것은 슬라이드 초안 하나뿐이므로 문구도 하나다.

브라우저 새로고침과 닫기는 커스텀 팝업을 사용할 수 없으므로 실제 dirty 상태일 때만 `beforeunload` 표준 경고를 등록한다.

## 저장 결과 알림

성공 알림은 작업을 막는 `alert` 대신 짧은 비차단 토스트로 표시한다.

- 슬라이드 저장: `슬라이드가 저장되었습니다` (메인 목록과 템플릿 모두 동일)
- 이동 가드의 저장 후 이동: `변경사항을 저장했습니다`
- 구조 커맨드: `순서를 저장했습니다`, `슬라이드를 삭제했습니다`(여러 개면 개수를 함께), `템플릿 이름을 변경했습니다`, `슬라이드를 복제했습니다: 이름`. 저장 버튼이 없는 자리에서 기록이 끝났음을 알리는 유일한 신호이므로 생략하지 않는다.

검증 오류는 해당 입력 근처 메시지 또는 기존 경고를 사용한다. 네트워크·업로드·생성 실패는 사용자가 놓치지 않도록 명확한 오류 메시지를 표시하고, 편집 상태와 활성 저장 버튼을 유지한다.

## 저장 중 보호와 즉시 저장

- 쓰기가 진행 중(`slideSaving`, `structureSaving`)일 때는 슬라이드 삭제, 선택 삭제, 순서 변경, 이름 변경, 되돌리기를 모두 거부하고 `저장이 진행 중입니다. 잠시 후 다시 시도해 주세요.` 토스트를 표시한다.
- 일반 슬라이드 목록의 순서 변경은 기존처럼 즉시 서버에 저장한다. 요청이 성공할 때까지는 새 순서를 확정하지 않으며, 실패하면 서버가 가진 이전 순서로 화면과 메모리를 되돌리고 `슬라이드 순서를 저장하지 못했습니다. 순서를 되돌렸습니다.`를 알린다. 저장 중에는 다음 순서 변경을 받지 않는다.
- 성경 말씀 슬라이드는 `/api/books`가 끝난 뒤에야 선택·기준 스냅샷이 만들어진다. 책 목록을 불러오지 못하면 성경 슬라이드 저장을 막고 `성경 책 목록을 불러오지 못했습니다. 새로고침한 뒤 다시 시도해 주세요.`를 표시한다.
- 스냅샷은 `customImageData`처럼 이미지 전체를 담는 필드를 길이와 앞뒤 일부만 남긴 대체값으로 바꿔 비교 비용을 입력 길이와 무관하게 유지한다. 이미지 교체, 제거, 원래 값 복원은 그대로 감지된다.

## 오류 처리와 일관성

- 서버 성공 응답 전에 저장 기준이나 `saved` 표시를 바꾸지 않는다.
- 비동기 저장 중 다른 이동 또는 중복 저장을 막는다.
- 저장 실패 후 사용자가 재시도할 수 있도록 초안과 파일 선택을 유지한다.
- 이동 중 저장이 실패하면 원래 작업 공간에 머문다.
- 템플릿 폐기는 서버에서 다시 읽거나 보존한 기준 스냅샷으로 복원해 로컬 캐시에 변경이 남지 않게 한다.
- 팝업 닫기, Escape, 배경 클릭은 `계속 편집`과 동일하게 처리한다.

## 테스트

자동 테스트가 가능한 상태 비교와 이동 결정 로직은 DOM과 분리된 순수 함수로 구성하고 다음을 검증한다.

- 저장된 슬라이드 선택 직후 저장 버튼 비활성
- 각 필드 수정 시 활성, 원래 값으로 복원 시 비활성
- 새 슬라이드 생성 직후 활성
- 저장 성공 후 비활성, 저장 실패 후 재활성
- 템플릿 슬라이드 저장 한 번으로 서버 반영, 그 뒤 버튼 비활성
- 슬라이드 저장 요청이 순서와 이름을 건드리지 않음
- 구조 커맨드가 슬라이드 내용을 건드리지 않고, 실패하면 되돌림
- 슬라이드와 템플릿이 동시에 dirty여도 이동 팝업 한 번만 표시
- 저장 후 이동 성공과 저장 실패 시 이동 취소
- 저장하지 않고 이동 시 새 슬라이드 제거와 기존 상태 복원
- 변경이 없을 때 내부 이동과 브라우저 종료 경고가 나타나지 않음
- 변경이 있을 때 브라우저 종료 경고가 나타남

수동 검증은 모든 슬라이드 타입, 파일 업로드, 찬송가 다운로드, 성경 슬라이드 생성, 탭·화면·템플릿 간 모든 이동 경로, 성공 토스트 문구와 오류 메시지를 포함한다.

## 완료 기준

1. 실제 저장할 변경이 있을 때만 해당 저장 버튼이 시각적으로 활성화된다.
2. 저장 성공 후 버튼이 즉시 비활성화되고 실패 후에는 다시 활성화된다.
3. 템플릿 작업 공간에서 저장은 한 번이며, 각 변경은 자기 범위만 기록한다.
4. 모든 내부 이동 경로가 동일한 단일 팝업 정책을 따른다.
5. 저장 실패나 변경 폐기 후 화면, 메모리, 서버 상태가 서로 모순되지 않는다.
6. 자동 테스트와 수동 시나리오 검증이 통과한다.
