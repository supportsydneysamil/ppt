# 슬라이드 컨트롤 메뉴 UX 설계

## 목표

PPT 슬라이드 편집 화면의 컨트롤을 실제 작업 범위와 일치시키고, 상태 변화로 인한 레이아웃 이동을 없애며, 슬라이드 단위 작업을 필요한 위치에서 쉽게 찾을 수 있게 한다.

버튼 수나 작업줄 길이를 줄이는 것 자체는 목표가 아니다. 다음 기준을 우선한다.

1. 버튼 이름이 실제 동작과 일치한다.
2. 상태가 바뀌어도 주변 컨트롤이 움직이지 않는다.
3. 현재 편집 중인 슬라이드와 목록의 특정 슬라이드에 대한 작업 경로가 분명하다.
4. 위험 작업은 빠르게 찾을 수 있되 실수로 실행하기 어렵다.

## 현재 동작과 용어

편집 헤더의 기존 `되돌리기`는 커스텀 편집기의 실행 취소 스택과 무관하다. 현재 슬라이드의 미저장 초안을 버리고 마지막 저장 상태를 다시 채우며, 슬라이드 선택과 편집 화면은 유지한다.

커스텀 편집 리본의 `실행 취소`와 `다시 실행`은 캔버스 편집 이력을 한 단계씩 이동한다. 두 기능은 복구 범위와 동작 방식이 다르므로 같은 용어를 사용하지 않는다.

## 편집 헤더

슬라이드 작업 그룹의 표시 순서는 다음과 같다.

1. `변경 취소`
2. PPTX 다운로드 아이콘
3. `저장`
4. 추가 작업 `⋯`

### 변경 취소

- 기존 `되돌리기` 라벨을 `변경 취소`로 바꾼다.
- 클릭하면 현재 슬라이드의 미저장 변경 전체를 버리고 마지막 저장 상태로 복구한다.
- 현재 슬라이드 ID, 목록 위치, 활성 카드와 편집기 표시 상태를 유지한다.
- 변경이 없으면 비활성화한다.
- 한 번도 저장하지 않은 새 슬라이드에서는 복구할 저장본이 없으므로 비활성화한다.
- 툴팁은 `저장된 상태로 되돌립니다`로 유지한다.
- 새 슬라이드를 버리는 작업은 추가 작업 또는 카드 메뉴의 `슬라이드 삭제`를 사용한다.

### 추가 작업 메뉴

편집 헤더 `⋯` 메뉴의 순서는 다음과 같다.

1. `슬라이드 복제`
2. `슬라이드 초기화`
3. `슬라이드 삭제`

`슬라이드 복제`는 현재 편집 중인 슬라이드를 복제하는 기존 목록 상단 `복제`와 같은 명령을 호출한다. 별도 복제 로직을 만들지 않는다.

## 저장 버튼

### 상태 표시

- 미저장 변경을 나타내던 텍스트 뒤의 점을 제거한다.
- 저장할 변경이 없으면 기존처럼 비활성 상태와 낮은 불투명도로 표시한다.
- 저장할 변경이 있으면 기존 브랜드 색상의 활성 CTA로 표시한다.
- 활성/비활성 색과 상호작용 상태만으로 저장 가능 여부를 나타낸다.
- 목록 카드의 `미저장` 배지와 이탈 확인 대화상자는 유지한다.

### 레이아웃 안정성

- dirty 상태 전환으로 저장 버튼의 너비가 바뀌지 않아야 한다.
- 저장 진행 상태에서도 버튼과 이웃 컨트롤의 위치가 바뀌지 않아야 한다.
- 버튼의 보이는 라벨은 모든 상태에서 `저장`으로 유지한다.
- 버튼 안에 스피너 자리를 미리 예약하고 저장 중에만 스피너를 표시해 너비를 고정한다.
- 저장 중에는 버튼을 비활성화하고 `aria-busy="true"`를 적용한다.
- `저장 중`, `업로드 중` 등 세부 진행 단계는 별도의 `aria-live="polite"` 상태 텍스트로 알리며 버튼 라벨을 바꾸지 않는다.
- 저장 버튼과 다른 헤더 버튼은 상태에 따라 DOM에서 나타나거나 사라지지 않고, 기존처럼 활성 여부만 바뀐다.

## 복제 진입점

복제는 다음 세 곳에서 제공한다.

1. 목록 상단 `복제`: 현재 편집 중인 슬라이드를 복제한다.
2. 편집 헤더 `⋯ > 슬라이드 복제`: 현재 편집 중인 슬라이드를 복제한다.
3. 슬라이드 카드 `⋯ > 복제`: 해당 카드의 슬라이드를 복제한다.

목록 상단과 편집 헤더의 명령은 동일한 대상과 로직을 공유한다. 카드 메뉴는 현재 편집 선택과 무관하게 메뉴를 연 카드의 ID를 명시적으로 전달한다.

복제본은 기존 규칙대로 원본 바로 아래에 삽입하고 새 이름을 만든다. 대기 중인 업로드 파일이 있어 안전하게 복제할 수 없으면 저장을 먼저 요구한다. 복제 중에는 같은 대상에 대한 중복 실행을 막고 진행 상태를 제공한다.

카드 메뉴에서 현재 편집 중이 아닌 슬라이드를 복제해도 편집 선택은 바꾸지 않는다. 복제 완료 후 새 카드가 목록에 나타나며, 현재 편집 맥락은 유지된다. 목록 상단 또는 편집 헤더에서 복제한 경우에는 기존 동작대로 복제본을 선택한다.

## 슬라이드 카드 메뉴

### 표시와 접근성

- 각 카드 오른쪽 위에 인라인 `⋯` 버튼을 둔다.
- 포인터가 있는 환경에서는 카드 호버 또는 포커스 시 강조해 표시한다.
- 터치 환경에서는 항상 사용할 수 있게 표시한다.
- 버튼은 키보드 포커스를 받을 수 있어야 하며 `추가 작업`이 아닌 카드 이름을 포함한 접근성 라벨을 제공한다.
- 버튼 클릭과 메뉴 항목 클릭은 카드 선택 및 드래그를 발생시키지 않는다.
- 한 번에 하나의 카드 메뉴만 열 수 있다.
- Escape, 바깥 클릭, 다른 메뉴 열기, 목록 다시 렌더링 시 메뉴를 닫는다.

### 메뉴 구성

카드 메뉴의 순서는 다음과 같다.

1. `복제`
2. `삭제`

`삭제`는 위험 작업 스타일로 구분한다. 위/아래 이동 버튼과 드래그 재정렬은 그대로 유지한다.

### 삭제 동작

- 저장된 슬라이드는 기존과 동일하게 확인 후 삭제한다.
- 한 번도 저장하지 않은 슬라이드는 기존과 동일하게 원격 삭제 없이 작업 목록에서 제거한다.
- 현재 편집 중인 슬라이드를 삭제하면 기존 인접 슬라이드 선택 규칙을 적용한다.
- 현재 편집 중이 아닌 슬라이드를 삭제하면 현재 편집 선택과 초안을 유지한다.
- 저장 또는 구조 변경이 진행 중일 때는 삭제를 실행하지 않는다.

## 상태와 데이터 흐름

- 헤더와 카드의 새 진입점은 기존 복제·삭제 도메인 로직을 재사용한다.
- 카드 명령은 카드의 슬라이드 ID를 인자로 받도록 명령 경계를 정리한다.
- 현재 편집 슬라이드용 기존 함수는 해당 ID 기반 명령을 호출하는 얇은 래퍼로 유지한다.
- 메뉴 추가가 dirty 판정, 저장 baseline, 커스텀 캔버스 history에 영향을 주어서는 안 된다.
- 다른 카드 작업 중 현재 편집 중인 dirty 초안을 암묵적으로 저장하거나 버리지 않는다.
- 다른 카드에 구조 변경을 적용할 수 없는 저장 상태라면 명령을 막고 기존 저장 진행 안내를 사용한다.

## 오류와 피드백

- 복제 또는 삭제 실패 시 대상 카드와 작업을 식별할 수 있는 기존 경고 또는 토스트 패턴을 사용한다.
- 서버 작업이 실패하면 로컬 목록을 성공한 것처럼 확정하지 않는다.
- 복제 성공 시 새 카드가 원본 아래에 나타난다.
- 삭제 성공 시 대상 카드가 사라진다.
- 진행 중인 카드 작업은 해당 메뉴 항목의 재실행을 막는다.

## 반응형 동작

- 편집 헤더는 현재 wrap 동작을 유지하며, 버튼 수를 줄이기 위한 별도 축약을 하지 않는다.
- 저장 버튼 너비 예약은 좁은 화면에서도 주변 컨트롤의 상태별 이동을 만들지 않아야 한다.
- 카드 메뉴 버튼은 터치 가능한 최소 크기와 카드 제목 영역을 침범하지 않는 공간을 확보한다.
- 긴 카드 제목은 메뉴 버튼 아래로 들어가지 않고 기존 줄바꿈 규칙을 유지한다.

## 테스트와 완료 기준

### 단위 및 소스 구조 테스트

1. 헤더 라벨이 `변경 취소`이고 기존 취소 동작에 연결된다.
2. dirty 점 스타일과 `is-dirty` 시각 점 출력이 제거된다.
3. 저장 버튼 상태 전환 및 진행 상태에서 레이아웃 너비가 변하지 않는다.
4. 헤더 `⋯`에 복제, 초기화, 삭제가 올바른 순서로 존재한다.
5. 카드 `⋯`에 복제와 삭제가 존재하고 대상 슬라이드 ID를 전달한다.
6. 카드 메뉴 이벤트가 카드 선택과 드래그로 전파되지 않는다.
7. 현재가 아닌 카드를 복제하거나 삭제해도 현재 편집 선택은 유지된다.

### 브라우저 흐름 테스트

1. 슬라이드를 편집하면 저장 버튼이 색으로 활성화되며 헤더 버튼 위치가 변하지 않는다.
2. 저장을 완료하면 저장 버튼이 비활성화되며 헤더 버튼 위치가 변하지 않는다.
3. 저장 진행 단계에서도 헤더 버튼 위치가 변하지 않는다.
4. `변경 취소`가 저장 상태를 복구하고 현재 슬라이드에 머문다.
5. 헤더 메뉴 복제가 현재 슬라이드를 복제하고 복제본을 선택한다.
6. 카드 메뉴 복제가 해당 카드를 원본 아래에 복제하고 현재 편집 선택을 유지한다.
7. 카드 메뉴 삭제가 저장 여부에 따른 기존 확인 규칙을 지킨다.
8. 카드 메뉴를 키보드와 터치 환경에서 열고 닫을 수 있다.

## 범위 밖

- 커스텀 캔버스 개체의 실행 취소, 다시 실행, 복제, 삭제 동작 변경
- 슬라이드 초기화의 의미나 확인 대화상자 변경
- 슬라이드 저장 모델 또는 서버 API의 전면 재설계
- 카드 이동 버튼 및 드래그 재정렬 제거
- 목록의 일괄 선택 및 일괄 삭제 흐름 변경
